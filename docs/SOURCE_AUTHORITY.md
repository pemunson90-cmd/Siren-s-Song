# Siren's Song — source authority routing

The canonical **current** hierarchy is maintained in [production SOURCE_AUTHORITY.md](https://github.com/pemunson90-cmd/Siren-s-Song/blob/gauntlet/production/docs/SOURCE_AUTHORITY.md). `main` is a historical/source-import entry; do not treat older documentation here as an alternative active Gauntlet policy.

Order of authority for active game design:

1. Latest explicit user decisions and ratifications.
2. Current living [game specification](https://github.com/pemunson90-cmd/Siren-s-Song/blob/gauntlet/production/docs/CURRENT_GAME_SPEC.md), interpreted with the ratified design bible.
3. Accepted concept selections and visual/design decisions.
4. Source-verified playable behavior, actual playtests and reproducible evidence.
5. Historical specifications, source-import records and recovered conversations.
6. Exploratory images, unratified suggestions and proposals.

Executable v7 is a **functional mechanic reference**. Its historical one-level process/approval constraints do not override current multi-mission production instructions. Historical source is preserved for provenance, not silently updated. Any disagreement between older handoffs and current user decisions must be classified and resolved in the active production guidance and task briefs. At task completion, automatically check for stale authority/status/handoff assertions and repair routine discrepancies without relying on the user.

The active Gauntlet remains open-ended. The user alone can authorize program termination; a worker's completion or any milestone only advances to the next task. Read the exact latest `gauntlet/production` instructions before work.
