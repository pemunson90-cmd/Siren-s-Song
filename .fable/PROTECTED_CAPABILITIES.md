## What this ledger is

This is the regression ledger for the engineering overhaul of Siren's Song (Godot 4.6.3, project in `game/`). Every row is a working capability that a player or a maintainer can reach today. Later work is checked against these rows so that nothing working is lost.

How to read a row:

- **ID** is a stable code. The prefix names the area (for example `CAMP`, `SIREN`, `SAVE`). In the campaign area the number of rows `CAMP-000` to `CAMP-041` is the operation's catalog ID. IDs are never reused. A capability that is removed on purpose keeps its row, with the decision that removed it.
- **Capability** is one sentence a player or maintainer would recognise. Numbers are quoted from the data tables named in the next column.
- **Where it lives** lists real paths relative to the repository root. Every path was checked to exist on 2026-11-11.
- **How to verify** names registered suites from `game/tests/suites.txt`. `core` means the checks inside `game/tests/run_tests.gd` (suite `run_tests`). `(render)` after a suite name means the suite is registered with the `render` backend: it cannot run on Windows locally and runs on GitHub. `RENDER ONLY` means every suite on that row is a render suite. `NO TEST` means no automated check exists and the plan should add one. A script name with a command means a tool test outside the suite registry.
- **Protected rule?** is `PAT` when `docs/USER_DIRECTIVES.md` or the recorded rulings make the rule Pat's call (Siren senses, sight ranges, lock, beam, collision, damage, hull, never disabling a Siren, ending conditions, story text, art direction, photo exposure and grading, and the release-control rulings of 30 October 2026). A `PAT` row may be moved or restructured in code. Its behaviour and numbers may not change without a ruling.

How to run a suite on Windows: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\toolchain\win\test-suite.ps1 -Suite NAME` (render suites are reported as SKIPPED). On Linux or CI: `scripts/toolchain/test.sh --suite NAME`. Thirty-four suites have a dash in the local column of `suites.txt` and are in the CI profile only (for example `combat_rules_tests`, `photo_capture_tests`, `all_stop_tests`, `a11y_cues_tests`). They still run by name.

The golden test `protected_rules_tests` pins many `PAT` numbers in `game/tests/fixtures/protected_golden.json`. It is one of three canary suites in `scripts/toolchain/canaries.txt` (with `control_mix_tests` and `crash_possible_tests`).
